# Threat model

The attacks considered, what stops each, and what is left. STRIDE-style; the controls are
described in [security.md](security.md) and [engine.md](engine.md).

| # | Threat | STRIDE | Actor | Mitigation | Residual risk |
| --- | --- | --- | --- | --- | --- |
| T1 | A custom SQL check, query dataset or filter writes to, locks or slows a source database | Tampering, DoS | Editor, API key with `manage` | sqlglot guard: one read-only SELECT, no writes, `INTO`, locking clauses, SET or PRAGMA, no side-effect or sleep functions, no table functions; read-only session on PostgreSQL, MySQL and SQLite; statement timeouts; transaction always rolled back; `max_concurrent_scans` per connection | SQL Server has no read-only session mode: a write that slipped past the parser would run with the login's rights. Use a `db_datareader` login. An expensive but valid SELECT still costs the source up to the statement timeout |
| T2 | A custom check on a file dataset reads the worker's files or reaches the network through DuckDB | Information disclosure | Editor | DuckDB guard (`read_csv`, `read_parquet`, `glob` and similar refused, no table functions or paths in FROM); after loading, `enable_external_access = false`, `autoload_known_extensions = false`, `lock_configuration = true`; the database is in memory and holds only the loaded files | None known |
| T3 | Source credentials are read from the database, the API or logs | Information disclosure | Anyone with database or log access, a curious user | Sealed with AES-GCM or KMS, context bound to the row; never returned (`has_password`, `target_hint`); `hide_parameters=True` on source engines; tested that no response or log line contains a source password | Whoever holds `LOCAL_MASTER_KEY` (local mode) or KMS decrypt rights can open them: protect the key, prefer `KEY_MODE=kms` |
| T4 | A connection, REST URL, webhook or AI endpoint is aimed at instance metadata to steal the task's credentials (SSRF) | Information disclosure, Elevation | Editor, admin | Link-local, unspecified and metadata addresses and names refused at save time and at call time against every resolved address; numeric IPv4 spellings canonicalised; redirects never followed | DNS can change between the check and the driver's own resolution (rebinding); on AWS, IMDSv2 and task-role scoping limit what metadata would give |
| T5 | REST datasets or webhooks probe the internal network | Information disclosure | Editor | Private and loopback addresses refused unless `OUTBOUND_ALLOW_PRIVATE=true`; responses capped; only the status and a short message are shown | Database hosts may be private by design (`SOURCE_ALLOW_PRIVATE=true`): an editor can test whether a private host and port answer. Set it to false where databases are reachable on public addresses only |
| T6 | A user reads another project's datasets, samples or incidents | Information disclosure | Signed-in user | Every project route resolves a `Principal`; roles per project; unseen projects answer 404; every query is filtered by project id | Instance admins see every project by design |
| T7 | An API key is used beyond its purpose | Elevation | Holder of a leaked key | Keys belong to one project; scopes `read`, `scan`, `push`, `manage`; owner routes refuse keys; only an HMAC with a pepper is stored; revocation is immediate | A key with `manage` can edit checks, including custom SQL (bounded by T1) |
| T8 | Personal data spreads through failing samples, reports or AI prompts | Information disclosure | Viewer, AI provider | Samples bounded by `sample_size` (0 keeps none); masked columns replaced before storage; AI off by default, samples sent only with `ai_allow_samples`, never for masked columns | Unmasked columns appear in samples and reports for every project member; downloaded reports are outside the platform's control |
| T9 | A planted value runs as a formula when a report is opened in a spreadsheet | Tampering | Whoever writes the source data | Cells starting with `=`, `+`, `-`, `@`, tab or CR prefixed with a quote | None known |
| T10 | Account takeover by password guessing | Spoofing | Outsider | argon2id; 5 failures lock for 15 minutes (Postgres, atomic); 20 sign-ins per minute per IP; dummy hash for unknown emails | Lockout can be used to annoy a known account for 15 minutes |
| T11 | CSRF against a signed-in editor | Tampering | Malicious site | `X-DQ-CSRF: 1` required on cookie mutations; SameSite=Lax cookie; CORS allowlist | None known |
| T12 | A signed-out or password-changed session keeps working | Spoofing | Holder of a stolen token | `revoked_sessions` in Postgres; `session_version` bump on password change | A stolen token is valid until sign-out or expiry (`SESSION_TTL_HOURS`) |
| T13 | A scan is lost, run twice, or its result overwritten when a worker dies or stalls | Tampering (integrity), DoS | Failure, not an attacker | Leases renewed by heartbeat; reaper re-queues expired leases up to `MAX_ATTEMPTS`; every write conditional on `(id, attempt, worker)`; completion in one transaction | A scan killed during its last query is re-run from the start, so the source sees that work twice |
| T14 | Two scans finishing together open two incidents or send two emails | Tampering (integrity) | Failure | Partial unique index on open incidents, unique `(incident, channel, event)` on notifications, `ON CONFLICT DO NOTHING` | None known |
| T15 | A forged alert webhook is accepted by the receiver | Spoofing | Outsider | `X-DQ-Signature: t=<time>,v1=<HMAC-SHA256 of "<t>.<body>">` with a per-channel secret; receivers verify and reject old timestamps ([alerts.md](alerts.md)) | Receivers that skip verification accept anything |
| T16 | Audit history is rewritten | Repudiation | Admin, attacker with the app's database login | A trigger refuses UPDATE and DELETE on `audit_log` | A database superuser can drop the trigger |
| T17 | Denial of service through large uploads or pushes | DoS | Outsider, API key | Bodies capped before parsing; large limits only for valid sessions or key-shaped credentials; uploads streamed to disk; scan requests limited per project (`SCAN_RPM`) | Volumetric attacks are for the load balancer and WAF |
| T18 | A huge or hostile file exhausts the worker | DoS | Editor | DuckDB `memory_limit` (`DUCKDB_MEMORY_LIMIT`), spill to the scan's temp directory, 4 threads; a timer interrupts DuckDB when the timeout passes ([engine.md](engine.md#timeouts)) | A file that fills the worker's disk fails its own scan and may slow others on the same worker until the temp directory is removed |
| T19 | The AI endpoint is used for SSRF or receives data it should not | Information disclosure | Admin | Metadata refused; private endpoints refusable (`AI_ALLOW_PRIVATE_ENDPOINTS=false`); AI off by default; drafted checks validated and accepted by a person | Prompts carry column names and statistics whenever AI is on |
